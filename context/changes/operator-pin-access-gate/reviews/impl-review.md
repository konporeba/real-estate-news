## Findings

### F1 — `.env.example` documents the superseded `hash-pin.mjs` invocation

- **Severity**: ⚠️ WARNING
- **Impact**: 🏃 LOW — quick decision; fix is obvious and narrowly scoped
- **Dimension**: Plan Adherence
- **Location**: `.env.example:23-24`
- **Detail**: Phase 2 originally planned `scripts/hash-pin.mjs` invoked via plain `node`. Mid-implementation this was adapted (with explicit user sign-off) to `scripts/hash-pin.ts` run via `tsx` — because plain `node` can't resolve TypeScript or the `@/` path alias `pin.ts` needs. That adaptation landed correctly everywhere else (`scripts/hash-pin.ts` itself, `package.json`'s `"hash-pin": "tsx scripts/hash-pin.ts"` script, the commit message), but `.env.example`'s comment was written in Phase 2 *before* the adaptation and never updated:
  ```
  # F-02: operator PIN access gate. PIN_HASH is generated by `node scripts/hash-pin.mjs <pin>
  # <pepper>` — do not type it by hand. ...
  ```
  This is documentation-only drift — it doesn't affect runtime behavior, since nothing reads `.env.example` — but it will send a future reader to a command that doesn't exist (there is no `scripts/hash-pin.mjs`).
- **Fix**: Update the comment to `npm run hash-pin -- <pin> <pepper>` (matching the actual `package.json` script and the guidance already given to the user during Phase 5).
- **Decision**: FIXED

### F2 — `Welcome.astro` still advertises sign-up in marketing copy

- **Severity**: 👁️ OBSERVATION
- **Impact**: 🏃 LOW — quick decision; fix is obvious and narrowly scoped
- **Dimension**: Scope Discipline
- **Location**: `src/components/Welcome.astro:68-71`
- **Detail**: Phase 5 fixed `Welcome.astro`'s two dead CTA buttons (`/auth/signin` + `/auth/signup`, both now 404) down to one "Operator Sign In" button pointing at `/auth/pin`. A feature-card paragraph in the same file was left untouched and is now inaccurate:
  ```
  <h3 class="mb-2 text-lg font-semibold text-white">Authentication Ready</h3>
  <p class="text-sm leading-relaxed text-blue-100/60">
    Built-in Supabase auth with sign in, sign up, and protected routes out of the box.
  </p>
  ```
  There is no sign-up flow anymore, and the auth mechanism is PIN-based, not Supabase Auth. Purely cosmetic — this is scaffold marketing copy on the home page, not user-facing product content — but it's a loose end in a file this exact change already opened for auth-related edits.
- **Fix**: Reword to something like "Operator access gate with PIN-based sign-in and lockout protection out of the box," or remove the sentence entirely.
- **Decision**: FIXED
